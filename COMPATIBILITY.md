# Engine v1 compatibility

## Authority and scope

`../engineV1.sb3` is authoritative. Its SHA-256 is `9e1142546660e0e6bcc30fe78e98f37b8d972db8f42eaef5e5b18313cd5aca3a`. `docs_sb3_audit.txt` renders the actual project blocks; `scripts/audit_sb3.py` generates that audit. The preserved Experiment 8 engine provides a second, independently maintained Python comparison.

Compatibility means matching source rules and matching tested decisions, outcomes, rankings and mutations under controlled inputs. It does **not** mean that entering the same integer seed in Python and TurboWarp produces the same experiment. Python uses independent PCG64 streams; Scratch/TurboWarp random generators and shuffle implementation differ.

## Exact rules

| Component | Source behavior implemented |
|---|---|
| Architecture | 9 inputs, 12 sigmoid hidden neurons, 3 linear outputs |
| Parameters | 108 hidden weights then 36 output weights, followed by 12 hidden biases and 3 output biases; float64 |
| Inference | Input-weight products summed in source order, then bias; no fast-math reassociation |
| Initialization | Independent real uniform draws in [-1, 1] |
| Histories | Opponent's last three moves; history tuples are oldest to newest; one-hot vector is newest first; absent history is zero |
| Actions | 1 rock, 2 paper, 3 scissors; strict greater-than selection retains the lowest output index on ties |
| Population | 100 networks; 30 sequential population permutations per generation |
| Self-play | 50 adjacent pairs per permutation; simultaneous decisions; 23 scored throws (three initial throws plus twenty further throws) |
| Original bots | Forward cycle, reverse cycle, rock/rock/paper; uniform choice among three kinds and three starting offsets; 20 throws per network per permutation |
| Fitness | Self-play net wins minus losses plus bot weight times bot net score, accumulated in the original round order |
| Selection | Top 20; fitness ties preserve the **last shuffled population order** |
| Replacement | Four passes over the ranked 20 parents produce 80 children, followed by the 20 unchanged elites; fitness resets |
| Mutation | Visit all 144 weights then 15 biases; draw integer 1..100, mutate if <=10, then draw real increment in [-0.2,0.2] |
| Ancestry | Child has one parent, a new identity, source reproduction-generation birth label, and next evaluated `first_generation` |

`mode="compatibility"` rejects settings that would silently alter these rules. Bot weight, root seed, run length and persistence/execution settings remain configurable. Use explicit general mode for other populations, networks, selection or mutation settings.

The source starts output selection at -1000. If every output is <=-1000, the original produces an invalid action. Python rejects that condition with an explicit error. It also rejects non-finite parameters rather than letting invalid arithmetic propagate.

## Differential evidence

- `test_core.py` compares twelve deterministic genomes over all 40 reachable histories with Experiment 8's scalar and vector inference. Actions match exactly; outputs use absolute/relative tolerances of 1e-12.
- `test_source_vm.py` executes the actual SB3 opcode graph through a small test-only interpreter: three genomes × all 40 histories, source mutation with an explicit interleaved draw tape, a complete 100-network tournament round with known pairings/bots, and source top-20 selection. Fitness and mutations match exactly in these tests.
- `tests/fixtures/sb3_inference.json` contains fixed parameters, observations, hidden activations, output activations, and actions for two genomes × 40 histories, generated by that source-block interpreter. A test checks the authoritative SB3 hash and compares both neural layers.
- Additional tests cover zero-output ties, invalid sentinel output, parent immutability, child ordering, zero-delta attempted mutations, exact NumPy/Numba evaluation under identical schedules, and RPS match outcomes.
- Seven unfamiliar-opponent implementations are compared directly with functions extracted from the frozen Experiment 8 source for controlled seeds and histories. These are independent research tools, not evolutionary fitness additions.

A live TurboWarp JavaScript VM was **not** executed. The limited Python SB3 interpreter is not a complete Scratch VM or a cross-language proof; it fails on unsupported opcodes. Cross-runtime pathological floating-point ties remain a limitation. No conclusion rests on similar-looking fitness curves.

## Generation and identity convention

Population snapshot `g` contains the population **evaluated at index g**, before reproduction. The experiment's `generation` field is the number of completed generations; a 1,000-generation run has snapshots 0..999 and a recovery checkpoint containing the next population at index 1000. Children created after snapshot g carry `birth_generation=g` and `first_generation=g+1`.

The final reproduction is saved so a completed run can be extended without changing its trajectory. Consequently a full 1,000-generation run stores 80,100 identities (100 founders + 80 × 1,000), including 80 not yet evaluated children. Historical archives containing only pre-reproduction populations can have 80,020 observed identities. This difference is intentional.

## Reproducibility guarantee

For the tested Python/dependency versions, resolved configuration, root seed and execution mode, uninterrupted, paused/resumed and concurrent scheduling produced identical genome records and fitness histories. Three random streams isolate initialization, evaluation and reproduction; checkpoints preserve each generator state and the next ID. Timing, process IDs and wall-clock metadata are intentionally not reproducible. General-mode BLAS results and dependency upgrades are not promised bit-identical across machines. Preserve the lock file, configuration and engine version with published research.
