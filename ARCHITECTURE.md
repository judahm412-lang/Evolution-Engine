# Architecture and source audit

Engine v2 is an independently installable package. Nothing imports from a working-directory-relative path. `config` validates resolved settings; `neural` owns immutable genomes and an activation registry; `environments` owns observations, transitions and population evaluation; `evolution` owns ranking, asexual reproduction and mutation. `runner` coordinates those interfaces. `storage` owns transactional history and checkpoints. The process scheduler and FastAPI dashboard are clients of those interfaces.

## Experiment 8 reuse decision

All nine source modules and both test/verification modules were inspected. `engine.py` is adapted into `rps_core.py`: the original scalar reference, 40 reachable histories, oldest-to-newest history tuples, newest-first one-hot inputs, simultaneous matches, scripted opponents and all-pairs tournament are retained. Counters are widened for longer matches. New compatibility policy inference preserves the source's addition order and rejects the source's invalid -1000 action boundary. Experiment 8 remains frozen rather than being modified to import an evolving dependency. Differential tests detect divergence between the frozen implementation and the shared v2 core used by both evolution and research.

`data_access.py` and `ingest.py` assume Four Worlds, 100-slot snapshots, fixed paths, and 10-generation archive chunks. Their formats and validation logic inform v2's arbitrary-namespace import adapters. Existing indexed genomes can be referenced read-only without copying their arrays. `championship.py` and `historical.py` contain useful tournament/cohort logic but hardcode worlds, generations, and file outputs; v2 uses the underlying match engine with user-selected saved cohorts. `generalization.py`'s causal opponents are adapted for independent evaluation. `diversity.py` contributes RMS distance, policy Hamming distance and deterministic descriptive clusters; v2 labels these clusters rather than species. `figures.py` couples SVG reports to static CSVs; v2 charts query stored statistics. `verify.py` writes verification.json, so it is not run directly against the preserved archive; unit tests and a read-only integration audit cover its relevant invariants. `run_all.py` rebuilds historical results and is deliberately not run.

## Source findings

The rendered block audit is `docs_sb3_audit.txt`, generated reproducibly by `scripts/audit_sb3.py`. A generation contains 30 random permutations, 50 adjacent pairs of 23 simultaneous throws, and one 20-throw randomly chosen bot per network per permutation. Bot scores are multiplied by the configured weight and added after each self-play round. Selection uses strict greater-than, hence ties retain the final shuffled order. Four passes through ranked elites create 80 children, then the 20 elites are appended with reset fitness. Mutation visits weights then biases; each parameter gets an integer 1..100 test <=10 and, if selected, an independent real uniform [-0.2,0.2] addition. Source birth labels refer to the reproduction generation; `first_generation` records the next evaluated population. Source mutation attempts and actual nonzero changes are both retained. Initialization is real uniform [-1,1].

## Persistence and execution design

One WAL SQLite database lives under an explicit runtime root. Genomes are immutable and namespace-qualified, snapshots reference identities, and a transaction commits an evaluated population and the next population checkpoint together. A current recovery checkpoint is written every generation; configured checkpoint frequency controls retained historical checkpoints. Safe pause boundaries are between committed generations. Exclusive advisory locks prevent duplicate schedulers and duplicate writers for the same experiment. Separate OS workers have independent PCG64 streams; the scheduler survives a browser or web-server restart.

General environment evaluation returns an `Evaluation` (component scores, outcome counts and tie order). The one-step continuous target environment proves that the evolution loop does not assume RPS inputs or three actions. Runtime caches are separate from inherited genomes and keyed by architecture, activation and parameter content. Sexual reproduction and adaptive topology are reserved for later versions.

## Public interfaces and dependency direction

`Genome` validates immutable parameter arrays, `forward` supports vector observations, and `record` round-trips inherited metadata. `Config` resolves TOML/JSON to strict nested models. `EnvironmentPlugin` defines reset/observe/step/evaluate; `Evaluation` contains total/self/bot arrays, outcome counts, ordering and additional components. `reproduce(population, evaluation, config, rng, generation, next_id)` returns next population and next ID, leaving parents untouched. `Store` owns identity, transactions and migrations; `run_experiment` coordinates a generation without depending on FastAPI. `manager.enqueue` and `scheduler` operate on stored commands. Research functions consume saved immutable genomes; they never feed analysis scores back into a run.

The dependency direction is CLI/API → manager/runner/research → evolution/environments/neural + storage/config. Runtime state lives outside genomes. Both v2 evolution and research call the same RPS policy/match core. The frozen Experiment 8 code is a reference/integration source only, not a required runtime import. Environment configuration currently enumerates rps/target; adding a plugin requires extending both its validated configuration and factory registry. Adding asexual alternatives later can extend the existing reproduction boundary and multi-parent-capable lineage schema.

The local UI consists of static HTML/CSS/JavaScript bundled in the wheel, with no frontend build or network dependencies. FastAPI publishes a machine-readable OpenAPI schema; CDN-backed Swagger/ReDoc pages are disabled to keep offline behavior and content policy consistent. SSE reports compact progress changes at a configured interval. Worker processes remain independent of web request lifetimes.

## Boundaries

Linux advisory locks and process accounting make Debian/Linux the supported v2 platform; Windows/macOS process management is unverified. Performance optimization is CPU-only. Importing a frozen SQLite source uses immutable read-only connections and rejects nonempty WAL files to prevent source mutation or silently ignoring uncheckpointed rows. Large histories are paged in the API, while full exports remain deliberate potentially large operations. The API is local single-user, without remote authentication or authorization roles.
