# Dashboard guide

Start with `python -m evolution_engine --data /absolute/path/my-lab serve`. Open <http://127.0.0.1:8765>. The API's machine-readable request/response schemas are at `/openapi.json`; mutations require `X-Evolution-Client: dashboard` and a matching origin. This is a single-user loopback service with no accounts, telemetry, external CDN, or arbitrary file/shell access. Remote sharing/authentication is outside v2.0.

## Workflow

1. **New experiment:** select Original Engine v1 or workspace defaults, name the run, choose generations, bot weight, seed and checkpoint settings. Compatibility locks source-defining controls. General mode exposes architecture, population, selection, mutation and environment. Advanced JSON overrides support every validated setting. Four Worlds creates a bot-weight sweep; replicas and sweeps are queued automatically. Single experiments are created before Start.
2. **Live monitor:** Start, Pause, Resume, Stop, and Extend run are backend operations. Pauses/stops occur at committed generation boundaries. Watch completed generations, active elapsed time, throughput/ETA, current worker, checkpoint, fitness components, diversity, distributions, mutation counts and descriptive clusters. SSE updates are throttled; stored statistics remain authoritative.
3. **Population history:** select a zero-based generation to see ranked networks and fitness components. Open a network or add the top ten to the tournament basket. For histories sampled with a stride, choose a retained generation.
4. **Network inspector:** inspect architecture, source birth label, first population, parent, descendants, actual mutations, layer weights/biases and historical fitness. RPS shows all 40 reachable decisions. Calculate outputs for a comma-separated input vector. Add individual networks to the tournament basket.
5. **Genetics:** choose a population to see colored clusters and founder ancestry. Trace a network's parent chain with a bounded depth, or compare two IDs by RMS distance and changed parameter count. Change generation to inspect historical lineage changes. Continue deep trees from displayed ancestors.
6. **Tournament lab:** add saved populations or historical champions, choose rounds, repeats, starting histories, independent opponents and seed, then run. Inspect ranking, matrix and opponent trials. Export JSON or reload a saved tournament. The draft basket and named baskets persist in SQLite; unavailable deleted-source entrants are visibly marked and cannot silently enter a tournament.
7. **Configuration & exports:** inspect the resolved config, checkpoints and event log. Download config, statistics, summary, population, champion or analysis. CLI/API also offer gzip. These exports do not replace a database backup.
8. **Experiments:** filter by name/config text, status, environment, creation date, minimum generations or observed fitness, and page through history. **Compare runs** displays stored fitness curves for selected histories.
9. **Settings:** set global worker count, scheduler poll interval, refresh interval, log verbosity and default experiment JSON (including retention/performance settings). Choose a storage location with launch `--data`; changing it through an arbitrary browser path is intentionally unavailable.
10. **Benchmarks:** displays persisted measurements from the CLI benchmark command, including per-component and worker scaling data. The release workspace includes the actual measured release artifact.

Closing the tab does not stop experiments. Stopping/restarting the web server does not reset history or checkpoint state. If the whole machine/app terminates the scheduler, launch `serve` with the same data root to recover interrupted workers. Failure messages are retained and retries are bounded. Stop or Pause a run explicitly when execution should cease.

## Data and accessibility boundaries

Controls use labels and native keyboard navigation. Charts are SVG with accessible metric names; underlying numbers are available in history tables and exports. Tables scroll horizontally at narrow widths; the navigation becomes a top section. Monitor charts show at most the latest 1,000 points. Experiment/population API pages cap at 200 items and ancestry at 200 nodes; source databases are never sent wholesale to the browser. Some research queries (e.g. full ancestry aggregation and large all-pairs analyses) can still be expensive for unusually large populations.

The creation and repeat forms preserve the complete supported seed range, 0 through 9223372036854775807, as decimal text. Fresh repeat seeds are generated by Python. In advanced JSON, quote a seed above JavaScript's exact integer limit; the main seed input is the preferred control. Configuration comparisons and exports retain exact seed text.

## Laboratory workflow

- **Storage Manager:** refresh measurements in the background; compare actual SQLite/WAL/SHM sizes with logical experiment estimates and their timestamps. Expand Size details for genome, history and checkpoint counts. Sort/filter/select experiments. The shared accounting remainder is not exact overhead.
- **Deletion:** select runs, choose Preview deletion, read every name/ID and dependency, create a backup first when needed, then explicitly confirm. Without a recently verified archive, an extra acknowledgment is required. Saved analyses survive with source markers unless removal is explicitly selected. Historical source files are never removed. All workers must be paused; a queued worker cannot race the final maintenance check.
- **Reclaim Storage:** a separate confirmation rebuilds SQLite after deletion. The job needs exclusive maintenance and approximately twice the database size plus 16 MiB free. It reports actual reclaimed bytes; logical estimates are not a promise of disk savings.
- **Backups:** Create workspace backup, follow background status, then Refresh backup list. Verify archive checks the archive hash, database, checkpoints and external references. Download saves the archive. Restore uses the displayed CLI command into a new directory. Imported historical databases remain external dependencies; missing/changed files are reported.
- **Experiments:** search IDs, names, notes, tags/config and provenance; combine tags, exact seeds, projects, dates, state, environment, fitness, generation and measured-size ranges. Existing tag suggestions show experiment counts. Selection persists while paging; bulk tag/project updates are atomic, and exports/backups show progress.
- **Journal:** edit hypothesis, expected outcome, observations, conclusions, follow-up and freeform notes without changing config. Script-like text is displayed literally. Export notes or create an offline HTML report with optional weights/lineage. Reports distinguish stored observations, derived descriptions and user interpretations; they are not restorable backups.
- **Repeat:** choose same/fresh seed, and leave ready or queue immediately. The new run records its source and gets a new identity. The source is preserved. A paused original is never resumed by this action.
- **Family Trees:** choose a saved network and ancestor/descendant direction. Pan, zoom, select, center, expand and collapse; change birth range or color. Fit shows all loaded nodes. Deep graphs require zooming or a focused branch. Tab/Enter selects nodes; arrow keys pan the graph. The expandable node/edge table is the text alternative. Missing ancestors stay unknown, and multiple recorded parents are rendered. Founder colors are limited to resolvable loaded ancestry; cluster coloring is explicitly unavailable for unrecorded membership.
- **Genetic comparison:** choose compatible networks, a layer and weights/biases. Click cells for exact values; page large sections. RMS uses all aligned parameters. Incompatible architectures/activations receive an explanation instead of a misleading distance.
- **Charts / Compare runs:** select metrics and generation range, zoom/pan, inspect the pointer tooltip, and export SVG or plotted JSON. Comparison ranges are synchronized. Raw extrema-preserving samples remain available; optional moving means are labeled as smoothing of plotted observations. Config differences classify scientific versus operational changes and preserve seed precision.
- **Evolution Replay:** play/pause, step, change speed, scrub or jump to a recorded generation/milestone. Aggregate-only generations explicitly disclose absent population snapshots; no population is reconstructed. View the saved champion and bounded family state.
- **Bookmarks / Timeline:** save named experiment, generation, network, branch, champion, tournament or event references. Search/edit bookmark notes and tags. The chronological timeline combines recorded events/checkpoints with separately labeled annotation dates. Run milestone detection with explicit criteria, then confirm/dismiss candidates and record review notes. Descriptive thresholds are observations, not causal discoveries.
- **System Resources:** inspect CPU, memory, live worker usage, queue and recent failures. Configure descending free-space thresholds. Disk pauses preserve committed state; free capacity and resume explicitly. Values come from Linux, not browser guesses.

Retention presets apply only to newly created runs: Detailed (stride 1 / checkpoint archive 10 / retain 100), Balanced (10 / 50 / 20), Compact (100 / 100 / 5). All retain immutable genomes, ancestry, every aggregate and the current recovery checkpoint. The displayed parameter estimate is a rough planning aid, not a physical-size forecast.

Selectors initially list recent experiments; use the paginated Experiments search to open older runs directly. Charts return at most 2,000 points and annotation overlays cap at 200. Replay loads recorded observations in bounded pages. Background jobs are not automatically retried after interruption. Keep the loopback server local; no cloud account or internet connection is needed.
